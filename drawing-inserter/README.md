# 도면 이미지 자동 삽입 도구 (Drawing Inserter)

특허 명세서 워드 문서에 도면 이미지를 자동으로 삽입하고, 삽입 결과의 정확성을 검증하는 Flask 기반 웹 도구입니다.

## 주요 기능

- 워드 문서(.docx)에 도면 이미지를 자동 삽입
- 파일명에서 도면 번호 자동 파싱 및 정렬
- 드래그앤드롭으로 삽입 순서 수동 조정
- 삽입 진행률 실시간 표시 (SSE)
- 삽입 전·후 다단계 검증 및 리포트 제공
- 도면마다 새 페이지 시작, 캡션 `【도 N】` 형식 자동 삽입
- 원본 파일 보존 (복사본에만 작업)

## 사용 방법

### 1단계 — 파일 선택

- 좌측 드롭존: 워드 문서(.docx) 1개 선택
- 우측 드롭존: 도면 이미지 파일 복수 선택 (`.png`, `.jpg`, `.tif`, `.tiff`, `.bmp`, `.gif`)
- 클릭 또는 드래그앤드롭 모두 지원
- 양쪽 파일이 모두 선택되면 **파싱 확인** 버튼 활성화

### 2단계 — 순서 확인

- 파싱된 도면 번호 순으로 썸네일 카드 자동 정렬
- 카드를 드래그하여 삽입 순서 수동 변경 가능
- 파싱 실패 파일은 경고 표시 후 자동 제외
- 검증 경고(번호 불연속 등)가 있어도 삽입은 진행 가능

### 3단계 — 삽입 결과

- **삽입 실행** 클릭 시 실시간 진행률 표시
- 완료 후 상세 리포트 자동 표시
  - 삽입된 도면 목록 (도면 번호, 파일명, 상태)
  - 제외된 파일 목록 (파싱 실패 사유)
  - 번호 불연속·중복 경고
- **결과 파일 다운로드** 버튼으로 완성된 .docx 저장

## 검증 시스템 상세

도면 삽입 도구는 사용자가 실수 없이 문서를 완성할 수 있도록 **삽입 전 파싱 단계**와 **삽입 완료 후 리포트 단계**, 두 단계에 걸쳐 검증을 수행합니다.

---

### 검증 판정 기준

| 상태 | 의미 | 삽입 가능 여부 |
|------|------|----------------|
| `PASS` | 모든 검증 통과 | 가능 |
| `WARNING` | 경고 있음 (번호 불연속, 파싱 실패 파일 존재) | 가능 (사용자 확인 권장) |
| `FAIL` | 오류 있음 (중복 도면번호, 유효 도면 없음) | 차단 |

---

### 검증 항목 1 — 파일명 파싱 실패

파일명에서 도면 번호를 인식하지 못한 파일을 감지합니다.

**인식 규칙:** 파일명에 `(숫자)` 또는 `(숫자+알파벳)` 패턴이 포함되어야 합니다.

```
파싱 성공 예시:
  특허도면(1).tif       → 도면 번호: 1
  도면파일(3a).png      → 도면 번호: 3a
  drawing(10).jpg       → 도면 번호: 10

파싱 실패 예시:
  도면설명.txt          → 숫자 패턴 없음
  image.png             → 괄호 없음
  readme.docx           → 지원하지 않는 확장자
```

**처리 방식:**
- 파싱 실패 파일은 삽입에서 자동 제외됩니다.
- 2단계 화면에서 경고 목록으로 표시됩니다.
- 모든 파일이 파싱 실패인 경우 → `FAIL` 판정, 삽입 차단

---

### 검증 항목 2 — 도면 번호 중복

동일한 도면 번호가 2개 이상의 파일에 존재하는 경우를 감지합니다.

```
중복 예시:
  도면A(3).tif
  도면B(3).tif   ← 번호 3 중복
```

**처리 방식:**
- `FAIL` 판정으로 삽입 차단
- 어떤 번호가 중복인지 오류 배너에 표시
- 사용자가 파일을 수정 후 재업로드해야 합니다.

---

### 검증 항목 3 — 번호 연속성 (갭 감지)

도면 번호가 순서대로 연속되지 않는 구간을 감지합니다.

```
갭 있는 예시:
  도면(1).tif
  도면(3).tif   ← 2번 누락
  도면(5).tif   ← 4번 누락
  → 갭 감지: [2, 4]

갭 없는 예시 (서브번호 포함):
  도면(3).tif
  도면(3a).tif  ← 3번의 보조 도면
  도면(4).tif
  → 갭 없음 (정수 번호 3이 존재하므로)
```

**처리 방식:**
- `WARNING` 판정, 삽입은 진행 가능
- 빠진 번호 목록을 경고 배너에 표시
- 의도적인 경우(예: 특정 도면 제외)라면 무시하고 진행해도 됩니다.

---

### 검증 항목 4 — 파일 무결성 검사

업로드된 이미지 파일이 실제로 열 수 있는 유효한 이미지인지 확인합니다.

```
검사 대상: PNG, JPG, TIF, TIFF, BMP, GIF
검사 방법: Pillow Image.verify() 호출
```

**처리 방식:**
- 손상된 파일은 업로드 단계에서 자동 제외됩니다.
- 이후 파싱 실패 목록에 포함되어 리포트에 표시됩니다.

---

### 검증 항목 5 — 워드 문서 유효성 검사

업로드된 .docx 파일이 정상적으로 열 수 있는지 확인합니다.

**처리 방식:**
- 손상된 docx 업로드 시 즉시 400 오류 반환
- 업로드된 임시 파일 자동 정리

---

### 검증 항목 6 — 파일 크기 제한

서버 과부하를 방지하기 위한 크기 제한을 적용합니다.

| 대상 | 제한 |
|------|------|
| 워드 문서 (.docx) | 최대 20MB |
| 이미지 파일 총합 | 최대 200MB |
| 요청 전체 | 최대 220MB |

**처리 방식:**
- 초과 시 HTTP 413 오류 반환 및 안내 메시지 표시

---

### 완료 후 리포트 구성

삽입이 완료되면 아래 항목을 포함한 상세 리포트가 화면에 표시됩니다.

```
[요약 배너]
삽입 완료 — 총 입력 10장 | 성공 9장 / 제외 1건

[삽입된 도면 목록]
 #  | 도면 번호  | 파일명              | 상태
 1  | 【도 1】   | 특허도면(1).tif     | 삽입됨
 2  | 【도 2】   | 특허도면(2).tif     | 삽입됨
 ...

[제외된 파일] (있을 때만 표시)
 #  | 파일명          | 사유
 1  | readme.txt      | 도면번호 인식 실패

[경고] (있을 때만 표시)
 ⚠️ 번호 불연속: [4, 7]
```

## 파일명 규칙

도면 번호는 파일명 안의 괄호 `( )` 안에 위치해야 합니다.

```
형식: [임의 텍스트](번호)[임의 텍스트].확장자

예시:
  특허도면(1).tif
  fig(2a).png
  drawing_final(10).jpg
```

서브번호(알파벳 접미사)를 사용하면 기본 번호와 함께 정렬됩니다.

```
정렬 예:
  파일(1).tif   → 1번
  파일(2).tif   → 2번
  파일(2a).tif  → 2번 다음 (2a)
  파일(3).tif   → 3번
```

## 제약 사항

- 지원 이미지 형식: `.png`, `.jpg`, `.jpeg`, `.tif`, `.tiff`, `.bmp`, `.gif`
- 지원 문서 형식: `.docx` (Word 2007 이상)
- 이미지 최대 너비: 14.5cm (A4 기준 여백 2.5cm)
- LDAP 인증은 미적용 (내부망 접근 가정)
- 동시 다중 사용자 세션은 job_id로 격리되나, 단일 서버 기준 설계
